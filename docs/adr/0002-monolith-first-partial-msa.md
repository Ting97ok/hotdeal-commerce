# ADR-0002. 모놀리식 우선 + 결제 도메인 부분 MSA 전환

- 상태: 확정 — 전환은 본편 완수 후 진행하는 **확정 범위**(기한이 아니라 순서의 문제) · 작성: 2026-06-10 · 갱신: 2026-07-03 (전환 대상 상향 — 결제 후속 처리 → **결제 도메인 자체**, 레포 전략·전환 단계 확정)

## 결정 요약

- **무엇을**: 모놀리식으로 완성한 뒤 **결제 도메인 1개 경계**만 별도 서비스(별도 DB)로 전환한다. 주문·재고는 잔여 모놀리스에 남긴다.
- **왜**: 일관성 요구가 다른 곳이 자연스러운 분리 경계 — 결제(외부 토스 정합·최종 일관성 허용)만 떼고, 오버셀 0(강한 일관성)인 주문·재고는 한 트랜잭션에 유지한다.
- **버린 대안**: 전면 MSA(분리 정당성 없는 곳까지 쪼개 인프라·운영 비용만 키움 — "정당성 없는 분리는 감점") / 후속 처리(알림·정산)만 분리(분리할 실체가 본편에 없어 "분리 위해 도메인 신설" 역전)
- **범위 밖(Non-Goal)**: 전면 MSA 인프라(게이트웨이·서비스 디스커버리·독립 배포), 재고 분리(최고 결합 도메인이라 강한 일관성 유지), 서비스 간 mTLS(내부망 신뢰 가정 — 성숙 시 승격)
- **트레이드오프**: 얻음 = 위험 경계(돈 정합)의 점진 전환 역량 증명 · 강한/최종 일관성 경계 분리 ↔ 잃음 = 분산 트랜잭션 복잡도(이벤트·Saga 보상·멱등), 서비스 넘는 correlation id 전파 필요
- **가역성**: **Type1**(되돌리기 어려움) — DB 분리·이벤트 계약은 한 번 가르면 비싸다. 그래서 본편(동시성·결제 정합) 완수 **후** 착수하는 확정 범위(기한이 아니라 순서의 문제).

## 컨텍스트

포트폴리오 목표에 "MSA 환경 플로우 이해(이벤트 기반 통신, Saga 보상, 멱등성)" 증명이 있다. 그러나 전면 MSA(게이트웨이·서비스 디스커버리·독립 배포)는 분리를 정당화할 근거(독립 배포·팀 경계·독립 확장 필요)가 없는 곳까지 쪼개, 인프라·운영 비용만 키우고 본편(동시성·정합성)에서 멀어진다.

## 결정

**모놀리식으로 완성한 뒤, "결제 도메인" 1개 경계를 별도 서비스(별도 DB)로 전환한다.** 주문·재고는 주문 서비스(잔여 모놀리스)에 남긴다.

- **레포 전략**: 현 저장소는 모놀리식 완성본 스냅샷으로 동결하고, **새 저장소(히스토리 복제)에서 전환**을 진행한다(멀티모듈: 주문 서비스 + 결제 서비스). 두 저장소는 README 상호 링크 + 전환 다이어그램으로 연결 — 전환 전/후가 저장소 단위로 보인다.
- **전환 단계**: ① 설계(경계·이벤트·보상) → ② 모놀리스 안에서 결제→주문 상태 전파를 이벤트 모양으로 비동기화(기존 테스트 유지한 채 결합 절단) → ③ 물리 분리(별도 모듈·DB + Kafka + Outbox) → ④ 정합 재검증(중복 전달·순서 역전·컨슈머 다운 시나리오).

### 갱신 이력 — 왜 "후속 처리"에서 "결제 도메인"으로 상향했나 (2026-07-03)

초안은 "결제 후속 처리(알림·이력·정산)"만 이벤트로 분리하는 최소 전환이었다. 다음 이유로 대상 자체를 상향한다:

1. **분리할 실체 부재**: 알림·정산 도메인은 본편에서 구현되지 않았다 — 후속 처리 분리는 "분리를 위해 도메인을 새로 만드는" 역전이 된다.
2. **커머스 MSA 의 표준 경계**: 실무에서 주문과 결제는 별도 서비스가 표준이다 — [우아한형제들 "결제플랫폼"](https://techblog.woowahan.com/15236/)이 실재 사례(각 주문시스템이 결제 연동을 플랫폼 형태로 제공받는 별도 시스템 + PG 대사로 정합 확인).
3. **위험 경계의 점진 전환이 증명 목표**: 돈 정합이 걸린 경계를 리스크를 통제하며 가르는 과정(단계 ②~④) 자체가 이 프로젝트가 증명하려는 핵심 역량이다.

## 근거 — 왜 그 경계인가

일관성 요구가 다른 곳이 자연스러운 분리 경계다:

| 영역 | 일관성 요구 | 소속 |
|---|---|---|
| 주문·재고 (구매 코어) | **강한 일관성** — 오버셀 0 은 한 트랜잭션이 답 | 주문 서비스 (잔여 모놀리스, 한 DB 유지) |
| 결제 (PG 연동·승인·해소) | 외부 시스템(토스)과의 정합 — 이미 [ADR-0008](0008-payment-model-pg-boundary.md) 어댑터 경계 + IN_DOUBT 해소로 **경계 내 완결** | **결제 서비스 (분리)** |
| 주문↔결제 상태 전파 | **최종 일관성 허용** — 확정 전 구간은 "결제 확인 중" 파생 상태로 노출(업계 표준: Adobe Commerce "Payment Review" 계열) | 이벤트(Kafka + Outbox) + 멱등 소비 |

- **재고는 분리하지 않는다**: 재고는 주문 생성(선점)·결제 승인(확정 차감)·만료/해소(복원) 세 흐름 모두와 원자성으로 묶인 최고 결합 도메인 — 강한 일관성 영역의 분산 전환은 부적합하다는 일반 지침과 일치([삼성SDS MSA 설계 고려사항](https://www.samsungsds.com/kr/insights/1239180_4627.html)). 분리 가능성만 이음새로 유지(재고 접근은 Service 경유·타 도메인 JOIN 금지·FK 값 참조 — [ADR-0003](0003-no-db-fk-constraints.md)).
- **주문 선생성(PENDING) 유지**: 분리 후에도 주문이 saga 의 상태 앵커다 — [microservices.io Create Order Saga](https://microservices.io/patterns/data/saga.html)가 정확히 "Order 를 PENDING 으로 먼저 생성"하는 구조([ADR-0004](0004-stock-reservation-lifecycle.md) 결정 1 이 분산 환경에서도 유효).
- **기존 정합 장치가 분산 방어로 승계**: 조건부 상태 전이(`UPDATE ... WHERE status=...`)는 그대로 **멱등 이벤트 소비자**가 된다(중복·지연 전달에 전이 1회 보장). 만료↔결제 역전 규칙은 [ADR-0004 결정 4](0004-stock-reservation-lifecycle.md)(재확보 되살림, 충돌 시 취소+보상)가 담당.

전면 MSA 미채택 이유는 초안과 동일 — 분리를 정당화하는 경계만 전환한다. **정당성 없는 분리는 감점**이다.

## 결과

- 전환 상세 설계(confirm 진입점, 동기 보상 + 이벤트 백업, 분리 후 안전망, 이벤트 스키마, 금액 스냅샷)는 후속 설계 문서에서 확정한다.
- 서비스 간 인증은 내부망 신뢰 가정 + 한계 문서화(성숙 시 mTLS 승격) — 요청 추적용 correlation id(서비스를 넘는 요청에 공통 ID) 전파는 최소 필수.
- 전환은 본편 완수 후 진행하는 **확정 범위**다 — 본편(동시성·결제 정합)은 완료됐고(2026-07-03 기준 B1·B2), 전환이 다음 순서다.
