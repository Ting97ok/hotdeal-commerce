# 코드 리뷰

현재 브랜치의 변경분을 리뷰한다. 판정 기준은 [CLAUDE.md](../../CLAUDE.md) 의 이 저장소 규약이고, Java/Spring 일반 패턴은 `spring-conventions` 스킬이다.

**코드를 수정하지 않는다.** 지적만 한다.

## 이 저장소에서 실제로 사고가 나는 지점

- **재고 차감 동시성·초과 판매** — `stock.deduct.strategy` 로 갈리는 구현 2개가 같은 계약을 지키는가. 한쪽만 고쳐 다른 쪽이 깨지지 않았는가. 조회 후 검사하고 저장하는 경로가 새로 생기지 않았는가
- **계층 경계** — Controller→Facade→Service→Repository. Service 가 타 도메인 Service 를 직접 부르는가
- **트랜잭션 경계** — 경계 밖에서 커밋을 가정하는가. 외부 호출이 트랜잭션 안에 들어갔는가
- **ExceptionCode 체계** — 새 예외가 `{Domain}ExceptionCode` 를 거치는가. HttpStatus 가 상황에 맞는가
- **응답 래핑** — 컨트롤러가 raw DTO 를 반환하는가. 테스트 단언이 `$.data.` 경로를 타는가
- **`infrastructure/{역할}/{벤더}` 배치** — 벤더 타입이 도메인으로 새어 들어왔는가
- **마이그레이션** — 엔티티 매핑 변경에 마이그레이션이 동반됐는가. 기존 `V*.sql` 을 고치지 않았는가

기계적 위반(탭·이중 래핑·계층 import·기존 마이그레이션 수정·FK 제약)은 `.claude/scripts/check.sh --all` 이 검출한다. 중복 보고하지 않는다.

## 보고

전부 보고한다. 확신 없는 것과 저심각도까지. **중요도로 스스로 걸러내지 않는다** — 선별은 사용자가 한다.

단 각 항목에 다음을 반드시 붙인다.

- `파일:행`
- **구체적 실패 시나리오** — 어떤 입력·상태에서 무엇이 잘못되는지
- 심각도와 확신도

**실패 시나리오를 쓸 수 없는 항목은 보고하지 않는다.** "여기 문제가 있어 보인다" 수준의 추측은 검증 비용만 만든다.

변경 파일이 없으면 그렇게 보고하고 끝낸다.
